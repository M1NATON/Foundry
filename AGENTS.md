## Оркестрация задач (если CLI поддерживает делегирование подагентам)

Если твой рантайм поддерживает разделение задач между агентами/моделями разного уровня —
маршрутизируй по сложности, а не отправляй всё в самую мощную модель по умолчанию:

- Тривиальные, низкорисковые правки (переименования, однострочные фиксы, очевидный
  boilerplate) → самая дешёвая/быстрая доступная модель.
- Обычная механическая работа (тесты, рефактор, форматирование, многофайловые
  правки без архитектурных решений) → модель среднего уровня.
- Глубокий анализ (архитектура, сложный дебаг, алгоритмы, решения с долгосрочными
  последствиями) → самая мощная доступная модель.

Правило экономии: по умолчанию пробуй самый дешёвый уровень, подходящий задаче.
Если задача тривиальна — начинай с дешёвой модели. Если она сообщает, что задача
сложнее ожидаемого — эскалируй на следующий уровень, а не переделывай сам с нуля.
Не отправляй тривиальные задачи сразу на топовый уровень "на всякий случай" — это
самый дорогой вариант и обычно избыточен.

Если делегирование недоступно — работай сам, но всё равно соблюдай приоритет
инструментов ниже.

Держи собственный контекст компактным: тяни в главный поток только финальные
выводы, а не промежуточные логи выполнения.

## Общие правила

- Отвечай на русском всегда.
- Используй Serena MCP для работы в проекте, если он подключён.

## Инструменты (MCP-серверы и хуки)

В окружении установлены и подключены MCP-серверы: Serena, graphify, context7.
Используй их ПО УМОЛЧАНИЮ. Игнорирование в пользу сырого grep/cat/find там,
где есть подходящий инструмент, — ошибка, а не стилистический выбор.

### Приоритет при исследовании кода (обязательный порядок)

1. **graphify** — сначала ориентируйся по графу знаний, если он есть.
2. **Serena** — затем работай на уровне символов (найти/понять конкретную сущность).
3. **Сырое чтение файла** — только когда нужно посмотреть/поправить конкретные строки,
   и предыдущие два шага не дали достаточно контекста.

ЗАПРЕЩЕНО использовать grep -r / find / cat целого файла для навигации по коду
или поиска символов, если Serena или graphify могут ответить на тот же вопрос.

### Serena (MCP) — семантическая навигация по коду

Language server для навигации на уровне символов. Используй ВМЕСТО сырого
чтения/грепа, когда нужно найти или понять код:
- `find_symbol`, `get_symbols_overview` — структура файла/класса без чтения всего файла.
- `find_referencing_symbols` — где используется символ.
- `replace_symbol_body`, `insert_after_symbol` — точечные правки на уровне символа.

Если проект уже активирован в Serena — предпочитай символьные инструменты чтению
целых файлов: это экономит контекст и снижает риск ошибки на устаревшей копии кода.

### graphify (MCP + хуки) — граф знаний кодовой базы

Если существует `graphify-out/graph.json`:
- ПЕРЕД чтением исходников по архитектурному/структурному вопросу — сначала
  `graphify query "<вопрос>"`.
- Для связей между двумя сущностями — `graphify path "<A>" "<B>"`.
- Для объяснения конкретного концепта — `graphify explain "<концепт>"`.
- Если существует `graphify-out/wiki/index.md` — используй его для широкой
  навигации вместо просмотра исходников вручную.
- `graphify-out/GRAPH_REPORT.md` читай только для широкого архитектурного обзора,
  или если query/path/explain не дали достаточно контекста.
- После изменения кода запускай `graphify update .` (AST-only, без затрат на LLM),
  чтобы граф оставался актуальным.

### context7 (MCP) — актуальная документация библиотек

Когда нужен API/пример по внешней библиотеке (Next.js, NestJS, Prisma, React и т.п.) —
бери документацию через context7, а НЕ по памяти модели:
1. `resolve-library-id` — получить ID библиотеки.
2. `query-docs` — задать конкретный вопрос по этой библиотеке.

Особенно важно для версионно-зависимых API — не выдумывай устаревшие сигнатуры.

### rtk (хук, если установлен) — сжатие вывода команд

Если настроен PreToolUse/before-hook для rtk: Bash-команды переписываются в
`rtk`-эквиваленты и вывод сжимается (git status, ls, ps и т.п.) на 60-90% токенов.
Ничего вручную вызывать не нужно — вывод команд уже отфильтрован автоматически.
