# Foundry: полное описание проекта для нейросети

> Актуально для текущего состояния репозитория. Этот документ описывает фактически реализованное поведение, а не только продуктовый замысел. Его можно передать нейросети как вводный контекст перед разработкой, отладкой или изменением интерфейса.

## 1. Кратко о продукте

**Foundry** — MVP-воркспейс для подготовки YouTube-видео. Он ведёт один ролик через последовательный производственный процесс:

```text
Project Library
  -> Research
  -> Script
  -> Storyboard / Scenes
  -> Images, video clips, voice and music assets
  -> Export
```

Пользователь создаёт проект, пишет текст дикторской начитки, превращает текст в сцены, редактирует каждую сцену, генерирует или загружает медиа и экспортирует результат в текстовый или структурированный формат.

Это не видеомонтажная программа в полном смысле слова. Текущий MVP организует сценарий, сцены, промпты и ассеты, но не рендерит готовый видеофайл.

## 2. Что уже умеет проект

- Создавать и показывать проекты в библиотеке.
- Показывать статус и прогресс проекта, количество сцен, число слов и расчётную длительность.
- Открывать полноэкранный редактор проекта.
- Писать сценарий с автосохранением через 1,2 секунды после изменения.
- Считать слова и примерную длительность начитки из расчёта 150 слов в минуту.
- Копировать специальный промпт для создания раскадровки во внешней нейросети.
- Автоматически разбивать сценарий на сцены через Gemini либо локальный fallback.
- Импортировать раскадровку из JSON, полученного от внешней нейросети.
- Создавать сцену вручную.
- Выбирать, редактировать, удалять и перетаскивать сцены на таймлайне.
- Редактировать voiceover, image prompt и video prompt сцены.
- Запускать генерацию изображения, клипа, голоса или музыки для сцены.
- Загружать собственные изображения, видео и аудио.
- Показывать статус каждого ассета и опрашивать API до завершения генерации.
- Удалять ассеты.
- Экспортировать проект в Markdown, TXT, JSON, CSV или SRT.

## 3. Основной пользовательский сценарий

1. Пользователь открывает `/` и видит библиотеку проектов.
2. Нажимает `New project`, вводит рабочее название и создаёт проект.
3. Нажимает карточку проекта и попадает в `/projects/{id}/editor`.
4. Открывает `Script`, пишет текст дикторской начитки и ждёт автосохранения.
5. Открывает `Storyboard` и выбирает один из вариантов:
   - `Split from script` для автоматического разбиения;
   - `Import storyboard` для вставки JSON из внешней нейросети;
   - `Add scene` для ручного создания сцены.
6. Выбирает сцену на таймлайне.
7. Редактирует voiceover и промпты в инспекторе справа.
8. Нажимает `Frame`, `Clip`, `Voice` или `Music`, чтобы запустить генерацию ассета.
9. Нажимает соответствующий `Upload`, чтобы прикрепить готовый локальный файл.
10. Перетаскивает сцены на таймлайне для изменения порядка.
11. Нажимает `Export` и скачивает нужное текстовое представление проекта.

## 4. Маршруты сайта

### `/` — Project Library

Главная страница и библиотека всех проектов текущего пользователя.

Показывает:

- заголовок `Library`;
- пояснение о проектах;
- кнопку создания проекта;
- сетку карточек проектов;
- skeleton-карточки во время загрузки;
- пустое состояние, если проектов нет;
- сообщение о недоступном API при ошибке запроса.

Карточка проекта содержит:

- обложку или декоративный placeholder;
- название;
- дату последнего изменения;
- количество сцен;
- количество слов, если сценарий существует;
- примерную длительность;
- текущий этап pipeline;
- индикатор прогресса.

Клик по карточке ведёт на `/projects/{id}`. Этот маршрут сразу перенаправляет в редактор `/projects/{id}/editor`.

### `/projects/{id}` — технический redirect

Не имеет собственного интерфейса. Перенаправляет на `/projects/{id}/editor`.

### `/projects/{id}/editor` — основной редактор

Полноэкранный workbench из следующих областей:

- верхняя панель `EditorChrome`;
- узкая левая навигационная панель `LeftRail`;
- центральный холст `Stage`;
- нижний таймлайн `Timeline`;
- перемещаемая плавающая панель инструментов `FloatingToolbar`;
- правый редактор сценария `ScriptOverlay`;
- правый инспектор сцены/раскадровки `InspectorPanel`;
- модальное окно экспорта `ExportPanel`.

При загрузке проекта показывается пульсирующий круг. Если проект не найден, появляется сообщение `Project not found` и кнопка `Back to library`.

## 5. Карта всех кнопок и элементов управления

### 5.1. Библиотека проектов

#### `New project`

- Где: страница `/`, над сеткой проектов.
- Что делает: заменяется inline-формой создания проекта.
- Поле формы: `Working title for the video...`.

#### `Create`

- Создаёт проект с введённым названием.
- Неактивна, если название пустое или запрос уже выполняется.
- Во время запроса показывает `Creating...`.
- Клавиша `Enter` в поле выполняет то же действие.

#### `Cancel`

- Очищает название.
- Закрывает inline-форму.
- Клавиша `Escape` выполняет то же действие.

#### `Start a project`

- Показывается только в пустой библиотеке.
- Сразу создаёт проект с названием `Untitled project`.
- Во время запроса показывает `Creating...`.

#### Карточка проекта

- Вся карточка кликабельна.
- Открывает редактор выбранного проекта.

В текущем UI нет кнопок переименования и удаления проекта, хотя API такие операции поддерживает.

### 5.2. Верхняя панель редактора

#### `Library` / стрелка назад

- Возвращает на `/`.
- На узком экране текст скрывается, но стрелка остаётся.

#### `Export`

- Открывает модальное окно выбора формата экспорта.
- Такая же операция доступна отдельной иконкой внизу левой панели.

Верхняя панель также показывает название проекта и человекочитаемый статус: `Draft`, `Research`, `Script`, `Storyboard`, `Producing` или `Ready`.

### 5.3. Левая панель редактора

Кнопки представлены иконками и имеют `aria-label`.

#### `Library`

- Возвращает в библиотеку проектов.

#### `Sources`

- Фактически переключает инструмент `script`.
- Открывает и закрывает редактор сценария.
- Несмотря на подпись `Sources`, отдельного UI для research/sources пока нет.

#### `Assets`

- Фактически переключает инструмент `frames`.
- Если сцена выбрана, справа открывается инспектор сцены с отфильтрованными IMAGE-ассетами.
- Если сцена не выбрана, появляется подсказка выбрать сцену на таймлайне.

#### Нижняя иконка `Export`

- Открывает то же окно экспорта, что и верхняя кнопка `Export`.

### 5.4. Плавающая панель инструментов

Панель можно перетаскивать за иконку-ручку. Позиция хранится только в React-состоянии текущей сессии и сбрасывается после перезагрузки страницы.

Повторное нажатие активной кнопки закрывает соответствующую панель.

#### `Script`

- Открывает правый редактор сценария.

#### `Storyboard`

- Открывает правую панель управления сценами.

#### `Frames`

- Открывает инспектор выбранной сцены.
- Список ассетов фильтруется до типа `IMAGE`.

#### `Clip`

- Открывает инспектор выбранной сцены.
- Список ассетов фильтруется до типа `VIDEO`.

#### `Voice`

- Открывает инспектор выбранной сцены.
- Список ассетов фильтруется до типа `VOICE`.

#### `Music`

- Открывает инспектор выбранной сцены.
- Список ассетов фильтруется до типа `MUSIC`.

### 5.5. Редактор сценария

Редактор открывается справа поверх холста. Его можно закрыть кликом по затемнённой области или клавишей `Escape`.

#### Большое текстовое поле сценария

- Хранит narration script.
- После изменения запускает автосохранение с задержкой 1200 мс.
- В шапке показывает число слов, расчётную длительность и состояние `Saving...`/`Saved`.
- Пустая строка допустима.

#### `Copy storyboard prompt`

- Видна только при непустом сценарии.
- Формирует инструкцию для внешней чат-модели вместе со сценарием.
- Копирует её в буфер обмена.
- На две секунды меняет подпись на `Copied`.

### 5.6. Панель Storyboard

#### `Split from script`

- Отправляет текущий сценарий на backend для разбиения на сцены.
- При наличии `GEMINI_API_KEY` backend пытается использовать Gemini.
- Без ключа или при ошибке Gemini используется локальный алгоритм: каждый абзац становится сценой.
- Существующие сцены и принадлежащие им ассеты заменяются новой раскадровкой.
- Во время запроса кнопка отключена и показывает `Splitting...`.
- Если сценарий пуст, API возвращает ошибку.

#### `Import storyboard`

- Открывает модальный диалог импорта JSON.

#### `Add scene`

- Создаёт сцену `New scene` с пустым voiceover в конце списка.
- Во время запроса кнопка отключена.

### 5.7. Диалог Import storyboard

Диалог закрывается кликом по фону, кнопкой `Cancel` или клавишей `Escape`.

#### `Copy prompt`

- Копирует prompt для внешней нейросети, построенный из сценария.
- Отключена, если сценария нет.
- После копирования временно показывает `Copied`.

#### Поле JSON

- Принимает JSON-ответ внешней модели.
- Backend извлекает и валидирует массив сцен.
- При ошибке парсинга/валидации сообщение отображается под полем.

#### `Import`

- Импортирует вставленную раскадровку.
- Отключена при пустом поле или во время запроса.
- Во время запроса показывает `Importing...`.
- Успешный импорт закрывает диалог и очищает поле.
- Импорт заменяет существующие сцены и их ассеты.

#### `Cancel`

- Закрывает диалог без импорта.

Важное текущее несоответствие: `InspectorPanel` передаёт в диалог `sceneCount={0}`, поэтому предупреждение о замене существующих сцен в текущем UI никогда не показывается, хотя сама замена выполняется backend.

### 5.8. Таймлайн

Таймлайн показывает временную линейку, общую длительность и карточки сцен. Длительность сцены берётся из `durationSec`; если она не задана, считается по voiceover. Минимальная визуальная длительность сцены — 3 секунды.

#### Карточка сцены

- Клик выбирает сцену и открывает её инспектор.
- Повторный клик по выбранной сцене снимает выбор.
- Карточку можно перетащить на место другой карточки.
- После завершения drag-and-drop новый порядок сохраняется через API.
- Карточка показывает thumbnail первого READY IMAGE/VIDEO-ассета, номер, название, длительность и статус.

Если сцен нет, показывается сообщение: `Timeline is empty - split the script or import a storyboard.`

### 5.9. Центральный холст Stage

Stage не имеет полноценного playback-контрола. Он показывает состояние выбранной сцены:

- если есть READY IMAGE/VIDEO-ассет, показывает первый такой ассет как key art;
- если сцена выбрана, но ассетов нет, показывает название и подсказку выбрать `Frames` или `Clip`;
- если сцен нет, показывает пустое состояние проекта;
- если сценарий существует, показывает его метрики и кнопку открытия сценария.

Видео сейчас также рендерится обычным `<img>`, а не `<video>`, поэтому настоящий загруженный видеофайл не проигрывается и может не отображаться как изображение.

#### `Open script` / действие пустого Stage

- Открывает редактор сценария.
- Точная подпись зависит от состояния, но действие всегда переключает tool на `script`.

### 5.10. Инспектор выбранной сцены

Показывает название сцены и номер `Scene 01`, `Scene 02` и так далее.

#### Иконка корзины `Delete scene`

- Удаляет сцену и все её ассеты каскадно.
- Сразу снимает выбор сцены.
- Во время запроса отключена.
- Подтверждение удаления отсутствует.

#### Поле `Voiceover`

- Редактирует narration этой сцены.
- Сохраняется при потере фокуса (`blur`), а не при каждом вводе.

#### Поле `Image prompt`

- Редактирует промпт для генерации изображения.
- Сохраняется при потере фокуса.

#### Поле `Video prompt`

- Редактирует промпт для генерации видео.
- Сохраняется при потере фокуса.

#### `Frame`

- Создаёт IMAGE-ассет и отправляет его в очередь.
- По умолчанию использует `imagePrompt` сцены.
- Если prompt пуст, API отвечает ошибкой.

#### `Clip`

- Создаёт VIDEO-ассет и отправляет его в очередь.
- По умолчанию использует `videoPrompt` сцены.

#### `Voice`

- Создаёт VOICE-ассет и отправляет его в очередь.
- По умолчанию использует `voiceText` сцены.

#### `Music`

- Создаёт MUSIC-ассет и отправляет его в очередь.
- В текущей реализации тоже использует `voiceText` как fallback prompt.

Все четыре кнопки генерации отключаются, пока выполняется mutation любого ассета.

#### Четыре кнопки `Upload`

Каждая кнопка расположена под соответствующей кнопкой генерации:

- IMAGE upload: `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`;
- VIDEO upload: `.mp4`, `.webm`, `.mov`;
- VOICE upload: `.mp3`, `.wav`, `.ogg`, `.m4a`, `.flac`;
- MUSIC upload: те же аудиоформаты.

Максимальный размер файла — 100 MB. Загруженный ассет сразу получает статус `READY`.

#### Карточка ассета

- Показывает preview, статус и тип.
- Для `QUEUED` и `GENERATING` отображается пульсирующий placeholder.
- Пока ассет не завершён, frontend опрашивает `GET /assets/{id}`.
- Для `FAILED` показывает ошибочный статус.
- Иконка корзины удаляет ассет; она появляется при наведении.

Текущий preview использует `<img>` для всех типов ассетов. Поэтому IMAGE отображается корректно, а настоящие VIDEO/VOICE/MUSIC-файлы не имеют специализированного `<video>`/`<audio>` проигрывателя.

### 5.11. Экспорт

Окно закрывается кликом по фону. Отдельной кнопки `Close` нет.

Каждая строка является кнопкой и сразу формирует и скачивает файл:

- `Markdown (.md)` — сценарий и breakdown сцен;
- `Plain text (.txt)` — только narration;
- `JSON (.json)` — полный payload проекта;
- `CSV (.csv)` — таблица сцен;
- `SRT (.srt)` — субтитры, рассчитанные по сценам.

Во время одного экспорта все форматы отключены. При успехе браузер скачивает файл, после чего окно закрывается.

Экспорт создаёт текстовые/структурированные файлы. Экспорт готового MP4 не реализован.

## 6. Сущности и связи данных

```text
Project 1 --- 0..1 Research
Project 1 --- 0..1 Script
Project 1 --- many Scene
Scene   1 --- many Asset
```

### Project

- `id`: cuid;
- `userId`: владелец;
- `title`: название;
- `coverUrl`: необязательная URL-обложка;
- `status`: этап pipeline;
- `createdAt`, `updatedAt`;
- владеет research, script и scenes.

### Research

- одна запись на проект;
- `sources`: JSON-массив источников `{ title, url, note }`;
- `notes`: общие заметки.

Backend и shared contract готовы, но отдельного research-интерфейса в web пока нет.

### Script

- одна запись на проект;
- `content`: полный narration;
- `wordCount`: число слов, вычисляет backend;
- `estSeconds`: примерная длительность, вычисляет backend;
- `updatedAt`.

### Scene

- принадлежит проекту;
- `order`: порядок на таймлайне;
- `title`;
- `voiceText`;
- `imagePrompt`;
- `videoPrompt`;
- `durationSec`;
- `status`;
- содержит ассеты.

### Asset

- принадлежит сцене;
- `type`: `IMAGE`, `VIDEO`, `VOICE` или `MUSIC`;
- `provider`: например `gemini`, `upload`;
- `prompt`;
- `status`;
- `url`: data URL, placeholder URL либо `/api/uploads/{filename}`;
- `errorMsg`;
- `createdAt`.

Удаление Project каскадно удаляет Research, Script, Scenes и Assets. Удаление Scene каскадно удаляет её Assets.

## 7. Статусы и производственный pipeline

### Статус проекта

```text
DRAFT -> RESEARCH -> SCRIPTING -> STORYBOARDING -> PRODUCING -> READY
```

- Новый проект создаётся как `DRAFT`.
- Сохранение research продвигает в `RESEARCH`.
- Сохранение script продвигает в `SCRIPTING`.
- Создание, split или import сцен продвигает в `STORYBOARDING`.
- Запуск генерации ассета продвигает в `PRODUCING`.
- Проект становится `READY`, когда логика завершения ассетов определяет готовность.

`ProjectsService.advanceStatus` продвигает статус монотонно и не откатывает его назад. Прямой `PATCH /projects/{id}` технически позволяет передать status из контракта, но UI этого не делает.

### Статус сцены

- `PENDING`: сцена создана, генерация не идёт;
- `GENERATING`: хотя бы один ассет в процессе;
- `READY`: ассеты завершены успешно;
- `FAILED`: генерация завершилась ошибкой.

### Статус ассета

```text
QUEUED -> GENERATING -> READY
                       -> FAILED
```

## 8. Как работает backend

API — один NestJS-сервис с глобальным префиксом `/api`.

### Persistence

- Prisma 6.
- PostgreSQL.
- `PrismaService` является общей границей доступа к данным.
- Все project-scoped операции проверяют, что проект принадлежит текущему `userId`.

### Очередь ассетов

- BullMQ использует Redis.
- Worker работает внутри того же процесса NestJS, что и REST API.
- Имя очереди задаётся в assets queue module.
- Concurrency worker: 2.
- После создания ассет имеет `QUEUED`, затем worker переводит его в `GENERATING` и в `READY` либо `FAILED`.

### Gemini и fallback

Разбиение сценария:

- с `GEMINI_API_KEY`: запрос к `gemini-2.5-flash`;
- без ключа или при ошибке: локальное детерминированное разбиение по абзацам.

Генерация изображений:

- с `GEMINI_API_KEY` и типом IMAGE: запрос к `gemini-2.5-flash-image`;
- результат сохраняется в БД как base64 data URL;
- без ключа или при ошибке создаётся локальный placeholder.

VIDEO, VOICE и MUSIC provider-интеграции пока не подключены. Для них worker всегда возвращает локальные placeholder-данные после короткой задержки. То есть кнопки и очередь работают, но реальное видео/аудио не генерируется.

### Загрузка файлов

- Multer сохраняет файлы на диск в каталог `uploads` относительно рабочей директории API.
- Имя файла: timestamp плюс очищенное исходное имя.
- API статически раздаёт каталог по `/api/uploads/`.
- Web использует относительный URL ассета.
- `apps/web/next.config.ts` проксирует `/api/:path*` на API origin, чтобы загруженные файлы открывались с web origin.

## 9. REST API

Все пути ниже имеют префикс `/api`.

### Projects

| Метод | Путь | Вход | Назначение |
|---|---|---|---|

### Script

|---|---|---|---|
| `GET` | `/projects/{projectId}/script` | - | Получить script или пустой default |

| `POST` | `/projects/{projectId}/script/split-into-scenes` | `{}` | Полностью пересобрать сцены из script |

| Метод | Путь | Вход | Назначение |
|---|---|---|---|

## 10. Авторизация и ownership

Весь REST API защищён общим `AuthGuard`.

- Если `CLERK_SECRET_KEY` не задан, используется dev-режим.
- В dev-режиме user id берётся из `x-user-id`, а при отсутствии заголовка равен `dev-user`.
- Если `CLERK_SECRET_KEY` задан, guard пока только требует `x-user-id`.
- Реальная проверка Clerk bearer token ещё не реализована и отмечена TODO.
- Сервисы проверяют ownership проекта перед чтением или изменением project-scoped данных.

Frontend сейчас не отправляет отдельный auth header и рассчитывает на dev-режим.

## 16. Важные ограничения и незавершённые части

1. Проект не собирает и не экспортирует готовый MP4.
2. Реальная генерация подключена только для IMAGE через Gemini.
3. VIDEO, VOICE и MUSIC generation возвращают placeholders.
4. Preview всех типов сделан через `<img>`; полноценные video/audio players отсутствуют.
5. Research API существует, но отдельного UI источников и заметок нет.
6. `Sources` в левой панели фактически открывает Script, а не Research.
7. Project rename/delete доступны в API/hooks, но кнопок в библиотеке нет.
8. Clerk token verification не реализована.
9. Загруженные файлы хранятся на локальном диске, без S3/object storage и без удаления физического файла при удалении записи Asset.
10. Для импорт-диалога из Inspector передаётся неправильный `sceneCount=0`, поэтому предупреждение о замене сцен скрыто.
11. В Inspector есть prop `onClose`, но визуальной кнопки закрытия нет; закрытие выполняется переключением tool/selection и внешними overlay-механизмами.
12. Ошибки некоторых mutations не имеют отдельного видимого UI-сообщения.
13. Генерация возвращает data URL, который хранится прямо в PostgreSQL-поле `url`; это приемлемо для MVP, но плохо масштабируется.
14. Локальная директория upload зависит от рабочей директории процесса API.

## 17. Правила для нейросети, которая будет менять проект

- Не считать документ продуктовым планом: сначала сверять конкретную реализацию с кодом.
- Сохранять простую MVP-архитектуру: один NestJS API и worker внутри API, без лишних микросервисов, CQRS и GraphQL.
- Перед изменением API payload менять Zod contract в `packages/shared-types`.
- Всегда проверять ownership для project-scoped операций.
- Продвигать pipeline status через `ProjectsService.advanceStatus`, если не требуется явная ручная установка.
- Хранить server state во frontend через TanStack Query.
- Хранить только локальный выбор tool/scene в `EditorProvider`.
- После mutations инвалидировать scene/project query caches.
- Соблюдать strict TypeScript, двойные кавычки и точки с запятой.
- В интерфейсе использовать существующие Tailwind-токены и редакционный workbench-язык дизайна.
- Не добавлять произвольные цвета и размеры, если для них уже есть проектный token.
- После изменения контракта сначала собрать `@foundry/shared-types`.
- Перед завершением задачи запускать test, typecheck и build; после исходников обновлять graphify.

## 19. Одноабзацное резюме для другого AI

Foundry — TypeScript pnpm/Turborepo monorepo с Next.js frontend, NestJS REST API, PostgreSQL/Prisma и Redis/BullMQ. Пользователь создаёт YouTube-проект, пишет narration script, автоматически или через импорт превращает его в упорядоченные сцены, редактирует voiceover/image/video prompts, генерирует либо загружает IMAGE/VIDEO/VOICE/MUSIC assets, переставляет сцены на таймлайне и экспортирует проект в md/txt/json/csv/srt. Реальная AI-генерация сейчас есть для разбиения сценария и IMAGE через Gemini; без ключа используются локальные fallbacks, а VIDEO/VOICE/MUSIC generation остаётся placeholder-функцией. Canonical API contract находится в `packages/shared-types`, ownership и монотонный pipeline — в `ProjectsService`, server state frontend — в TanStack Query, локальный выбор инструмента и сцены — в `EditorProvider`.
